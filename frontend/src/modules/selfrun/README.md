# SelfRun — 自我运转前端

> 文档对齐 v3.64.56 ｜ 最后核对 2026-11-14

生命周期五页签：**制定配置 → 本周状态 → 本月状态 → 历史复盘 → 阶段总结**。
页签与路由**同源**（`route.name` 后缀），从页头入口进来直接落在对应页签。
另有一页**不属于这五个页签**：`阶段账本`（长阶段详情，见文末）。

## 🔴 入口在页头，不在侧边栏（v3.64.0 起）

自我运转**不占侧边栏菜单项**（`menuConfig.ts` 里那四项已撤）。入口是 `LayoutHeader.vue`
右上角那个下拉 —— 它原来叫「日视图 / 周视图 / 月视图 / 年视图」，是个空壳
（点完只 `dispatchEvent('time-dimension-change')`，全仓无人监听）；现在它是真入口：

| 下拉项 | 路由 | 说明 |
|---|---|---|
| 制定配置 | `selfrun-setup` | 生命周期的第一段，也是**没有阶段时唯一的出口** |
| 本周状态 | `selfrun-week` | 默认落地页（`/selfrun` 就重定向到这里） |
| 本月状态 | `selfrun-month` | |
| 历史复盘 | `selfrun-review` | 「阶段总结」是它旁边的深层页，只从页内页签进 |
| 阶段账本 | `selfrun-stage`（`:id?`） | 长阶段详情（v3.64.19）—— **不渲染页签**，见文末 |

- 页头标签：在模块外显示「自我运转」，在里面显示当前页名（含**四个**配置子页都归到「制定配置」）。
- 🔴 **路由全部保留**：下拉里有 5 个直达项，删路由＝点开空白页（本项目老坑）。
- 🔴 `selfrun` **分组**仍留在 `defaultGroups` 与后端 `DEFAULT_MENU_GROUPS` 里：
  删分组要动库、会打乱用户拖过的顺序；`LayoutSidebar` 对空分组自动跳过，不会留空标题。
  副作用只有一个：菜单管理页会显示「自我运转 · 该分组暂无菜单项」。
- 页内回程靠页签 + 页头「← 制定配置」，**不用 `router.back()`**。
- 🔴 **阶段天数由后端 `days_label` 给**（v3.63.13）：`第 N 天` / `共 N 天` / `还有 N 天开始`；前端不自己算 `today - start + 1`，也不各自写三元表达式。
- 🔴 **阶段区间由后端 `range_label` 给**（v3.64.10）：`2026-11-01 ~ 2026-12-31（61 天）` / `2026-11-01 起（不设终点，手动收尾）`。起止日期**只此一份**，页头 / 仪表盘卡 / 阶段总结 / 已收尾列表都印它 —— `days_label` 刻意**不回带起点**（否则同一行会像两个不同的值）。**页面里不许再手拼 `start_date ~ end_date`。**
- 🔴 **相位词也由后端给**：`status_display` 在「active 但还没到起点」时是「未开始」，页头 tag 配色同步转中性（`elapsed_days > 0` 才绿）—— 否则同一行会出现「进行中 · 还有 1 天开始」。

### 🔴 阶段有两类，别用 `status` 去分（v3.64.56）

`SelfRunStage.stage_kind ∈ {run, record}`，与 `status` **正交**：

| 类型 | 是什么 | KPI / 周期 | 在哪管 |
|---|---|---|---|
| `run` | 运转型：这段路要考核 | 有 | 主视图（改 KPI、收尾）/ 阶段账本 |
| `record` | 记录型：「那几年我在哪儿」（小学期、谋生期…） | 永远没有 | `StageTimeline.vue`（补录 / 改 / 删） |

- 🔴 **不能拿 `status='closed'` 顶替记录型**：会污染「已收尾的阶段」表（那张表带「用它开新阶段」）、
  让 `is_long_stage`（= 顶级 + 零 KPI）把「小学期」判成**长阶段**、并让 `closed` 同时表示
  「有 Period 定格」和「永远没有 Period」两件事。三处都不报错，只是让列表半年后不可信。
- 🔴 **`GET /selfrun/stages/` 默认只返回 `run`**。要人生档案必须显式 `?kind=all`（或 `?kind=record`）。
  这个默认值的意义就是「老调用方零改动即正确」——新写的调用方**不要以为拿到的是全部**。
- 🔴 运转型**任何一层都不给删除**（它有 KPI 与已归档 Period）。子段（如「三年赎回期 › 离职适应期」）
  同样是运转型：模板里主行与子段是**两处渲染**，改判据必须一起改（类型检查看不出多了一个按钮）。
- 空档只在「段与段之间」和「最后一段之后到今天」产生，**第一段之前不计入**。顶层区间按**并集**扫 ——
  嵌套（长阶段包小阶段）或重叠（两段并行）时「相邻相减」会算出负数天，而列表看起来完全正常。

- `stores/selfrunStore.ts`：阶段 / 周期 / 模板 / 读数状态与动作
- `api/selfrunApi.ts`：模板、阶段、按期设定、打卡、归档 / 重开、总结、overview 封装
- `types/selfrunTypes.ts`：类型 + 枚举**副本** —— 真源是后端 `selfrun/constants.py`，**改常量必须同步改这里**（漏改不报错，只会少选项或落兜底）

## 时段轴（「这周我做了什么」，v3.64.35 / v3.64.39）

**同一张卡出现在两个页面**，用的是同一个组件 `WhatHappenedCard`：

| 页 | 位置 | 出现条件 |
|---|---|---|
| 历史复盘（抽屉） | 复盘信下方 | 有 `extras` 就显示（周看时段、月看清单） |
| 本周状态 | 「归档这一周」按钮**下方** | **周** + **未归档** |

🔴 两处各写一份的代价：复制出去的那份早晚与这份分家，**而且分家时不报错**，
只是两个页面上同一件事的数不一样。改口径只改 `WhatHappenedCard.vue` 一个文件。

🔴 本周状态页的数据来自 `GET /periods/current/` 的 `extras` —— 后端**一直都在返回**
（与 `periods/<id>/` 同一个 `compute_period_extras`），是 store 的 `applyCurrent`
只挑了七个字段、把 `extras` 丢了。现在 `PeriodView.extras` 存下来，零新增接口。

⚠️ 为什么本周状态页只在**未归档**时显示：归档后这一期的结论已定格，回头看请走
「历史复盘」（那里读的是同一份现算数据，但能对着冻结快照读，两处数不一致时说得清）。

本卡里的两个视图读的是同一份 `extras.what_happened`：

| 字段 | 给谁用 |
|---|---|
| `columns` | 时段轴的列（周期内**每一天**，没记录的天也占一列） |
| `blocks` | 时段轴的块：`{date, from, to, minutes, task_name, attribution, split}` |
| `span` | 纵轴范围（**主体块**的 `from` 最小值 → 全部块的 `to` 最大值） |
| `truncated` | 超上限被丢掉的块数，非 0 必须显示 |
| `days` | 清单视图（同名任务**合并**后的小时数） |

🔴 三条不能动的地方：

1. **`from`/`to` 是「当天第几分钟」，不是时间串。** 组件里一个 `new Date()` 都没有 ——
   拿到 `'09:00'` 就会有人解析，`USE_TZ` 下差 8 小时，而且结果看起来完全合法。
2. **纵轴不固定 0–24，也不是「取所有块的最早最晚」。** 记录多半从 7 点起，固定满格会把白天
   压成一条缝；但取所有块又会让一条 5 分钟的跨午夜尾巴把纵轴拉回 00:00（W42 实测：51 分钟
   残片换来 235px 空白）。后端 `span` 只让**主体块**定上边界，组件照用，并保底 4 小时。
3. **块与清单必须对得上。** `Σ blocks.minutes ÷ 60 == days[i].total_hours`，
   后端有测试守着。图可以难看，但不能和清单说两个数。

⚠️ **落在 `span` 外的块不按位置画。** 它们只可能是跨午夜切出来的短残片（`offMarks`）：
夹到最上面那条线上会读成「06:55 开始干了 37 分钟」。改为在列顶标「＋37m」，
`title` 给「纵轴从 06:00 画到 24:00 + 完整时段」，图例下再解释一次。
**位置是这张图唯一的信息 —— 宁可只报数，不许画错位置。**

⚠️ 跨午夜的记录在图上占两列（`split=head/tail`，虚线边），而清单里只在**开始那天** ——
「发生在哪天」和「记在哪天」是两件事。

⚠️ **月度不给时段轴**（31 列 × 24h 挤进 720px = 每列 20px），页头写明「（月度列太多，用清单）」。
默默少一个按钮会让人以为没做完。

⚠️ 重叠只在**像素级遮挡**时才分栏（2px 容差）。库里有 18 秒级的重叠，
按秒判重叠会把一整天每块都劈成两半。真正的时段重叠口径在 `temporal` 的导入预演里，不在这里。

## 阶段账本（`/selfrun/stage/:id?`，v3.64.19）

「一段长路」的一屏：**时间 / 钱 / 作品 / 它下面的小阶段**。数据全部来自
`GET /api/selfrun/stages/<pk>/ledger/`（**只读现算、零写库**）。

### 🔴 它为什么不是第六个页签

长阶段按设计**不产生 `SelfRunPeriod`**（同一周若同时属于长阶段与叶子阶段，判定会打两遍，
而「本周 0/5」算谁的就说不清了）。所以「本周 / 本月 / 按期修订 / 归档周期」在长阶段身上
**一件都做不了** —— 摆出页签只会让人点进去看到空。这一页在模板里是页签的**兄弟节点**：

```
<StageLedgerPanel v-if="isLedger" />
<template v-else>  …暂停横幅 + 两把尺子 + 五个页签… </template>
```

页头在账本页**不显示**：阶段状态 tag、`阶段名 · 区间 · 第 N 天 · N 条 KPI` 那行、
握手按钮、暂停/恢复。理由：那几样说的都是「正在跑的那个小阶段」，而这一页讲的是长阶段 ——
并排放在一行会被读成同一个阶段的两个状态。长阶段自己的身份在页内的身份卡上。

### `:id?` 为什么可选

页头下拉只会 `push({ name: 'selfrun-stage' })` —— 它拿不到「哪一段路」，也不该猜。
不带 `id` 时页面自己取**正在跑的那个长阶段**（顶层同一时间只允许一个 open，所以唯一）；
一个都没有就落到空态，说明长阶段是什么、以及去哪建。

### 四条显示口径（都踩过）

1. **六类小时印两位小数**，且「已记录」= 六格之和。印一位时六格加起来 34.00、
   总数写 33.96 —— 页面自己打自己脸（后端 `covered_hours` 已改成「六格之和」）。
2. **覆盖率的进度条封顶、数字照实**。v3.64.22 起**分子分母都不含睡眠**
   （分母是「每天可支配小时」，v3.64.25 由 12h 调到 14h），所以 141.5% 那种超 100% 不该再出现；
   仍不夹上限，留「一天醒着 16h、可支配按 14h 估」的少量越界余量。
   🔴 文案里的「按每天 Nh 可支配估算」读 `time.theoretical_daily_hours`，**不写死** ——
   写死就等于把后端常量复制一份到前端，改口径时必然只改一处。
   🔴 剔除量必须印出来（「睡眠 12.2h 已剔除」）—— 静默剔 12h 会让「维持」
   凭空少一块而屏幕上没有任何线索。
3. **零态查表**：`support_until === null` 时**不许**自己猜语义，读 `support_zero_reason`
   查 `SUPPORT_ZERO_LABEL` / `SUPPORT_ZERO_HINT`。从前这里印「永不耗尽」——
   把「还没有速度可外推」读成了「钱花不完」，方向正好相反。
4. **加载失败 ≠ 没有数据**（v3.64.27）。`stage === null` 有两种相反含义：
   「真的没有长阶段」和「有，但没取到」。只用一个 ref 表达两件事，失败时必然印成
   「还没有长阶段」，还劝用户去建一个已经存在的阶段。所以另立 `loadError`：
   失败时显示后端 `detail` 原话 + 重试，**优先于**空态。
   🔴 不要用 `apiErrorText` 取这句话：它对**所有 5xx** 返回兜底话术，
   正好把 503 里那句「请先执行数据库迁移」盖掉。调用点先取 `detail`，取不到才回落。

### 小阶段的「进详情」只给正在跑的那个

`SelfRunHub` 的周/月/总结三页读的都是 `store.stage`（当前阶段），**没有「打开任意阶段」的能力**。
给已收尾的小阶段挂个按钮，点下去会打开另一个阶段的数字 —— 比没有按钮坏得多。
所以只有 `child.id === store.stage.id` 的那一行有入口，其下用一句话指向「历史复盘」。
