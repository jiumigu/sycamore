## 媒体预览（v3.64.64）

清单里的 40px 缩略图**必须是 `el-image`**，不能用裸 `<img>`：裸图没有任何点击行为，
界面上是个「看起来能点、点了没反应」的小方块（v3.64.34 起一直是这个状态，v3.64.64 修）。

三个必须一起对的点：

| 点 | 做法 | 不这么做的后果 |
|---|---|---|
| 预览层 | `:preview-teleported="true"` | 弹层留在 `el-table` 里被 `overflow` 裁掉，只看见一条缝 |
| 预览列表 | `imageUrls(w)` = 该件**全部图片** | 只能看封面，角标 `+N` 说还有 N 张却翻不到 |
| 数量角标 | `extraImages(w)` = **图片数 − 1** | 按 `media.length` 数会把视频算进去 ⇒ 角标 +1、点开翻 0 张 |

- `cursor: zoom-in` 与 `@/shared/components/MediaGallery.vue` 保持一致 —— 能点就得看得出来能点。
- 视频（`media[0].type === 'video'`）点开用 `el-dialog` + 原生 `<video controls>`，不自造播放器。
- ⚠️ 已知边界：**视频只有排在第一位时才露面**。目前库里媒体全是图片；出现「封面是图、后面跟视频」时再处理。

### 缩略图（v3.64.72）

列表格子的 `src` 是 `media[0].thumb || media[0].url`：前者约 3–4KB，后者 110–466KB。

| 位置 | 用什么 | 为什么 |
|---|---|---|
| 列表 40px 格子 | `thumb`（后端派生的 200px JPEG） | 改造前是下载 400KB 原图来画 40px |
| `preview-src-list` / 预览层 | `url`（原图） | 拿缩略图做预览 = 把「看细节」悄悄降级成 200px，且不报错 |
| `thumb` 为 `null` | 回退 `url` | 历史图没补生成时不能显示裂图 |

🔴 `imageUrls(w)` 必须继续用 `url` —— 它同时是预览列表与 `+N` 的分母，换成 `thumb` 会让角标数对但点开全是糊的。


## 列表筛选（v3.64.71）

卡片头一行：**类型下拉** + **关键词** + **清除**，外加「共 14 件 · 筛出 5 件」。

| 判据 | 为什么 |
|---|---|
| 三个筛子（出口卡 / 类型 / 关键词）**相乘**，`narrowed` 一个 computed 判「是否在筛」 | 各自判各自的会漏：只判 `workFilter` 时，只输关键词得到的空结果会被说成「还没有作品」 |
| 类型选项取 `store.kindOptions`（后端**全量 9 类**），不是「当前在用的那几类」 | 筛选项回答的是「我有没有做过刺绣」，选到 0 件是真答案；藏起来就没法问 |
| 关键词只匹配 `name / summary / note / origin[].title` | `kind_display` / `status_display` 已有专门入口，再匹配一次等于同一个问题两个答案 |
| 点「累计件数」= `clearFilters()`（三样一起清） | 那个按钮的意图就是「看全部」；只清出口会剩一个说不清的结果 |
| 状态标签的 `close` 只清它自己 | 它只代表出口这一个筛子 |
| 计数**两个数一起给** | 只给筛后的数要用户记住原来几件；只给总数，则「共 14 件」配 3 行更莫名其妙 |

**不加分页。** 实测 14 件 / 6.5KB / 13–25ms / 2 条 SQL / 序列化 3.6ms（`prefetch_related('captures')` 已挡住 N+1），
而作品是「一年几十件」的量级。分页在这里不是性能措施，是**制造「翻页找不到」**。
真到几百件时按这个顺序动：① `el-table` 渲染行数 → ② 接口 `limit/offset`
（媒体体积已于 v3.64.72 解决：列表 5 张图 1.70MB → **17KB**）。

## 边界

- 七个入口是**同一个勾**，不要在某个源页面里另存「值得留」字段 —— 那就是第二份真源。
- 「待提炼」量的是**捕获**（还没成形的东西），与上面的作品清单不是同一类，所以点它开明细、不筛表。
- 作品媒体是**媒体真源**；展厅馆藏只引用，不重复上传。
