# Sycamore - 个人人生管理系统

一个覆盖人生七大维度的私人管理系统：时间感知、目标达成、财富管理、关系维护、健康追踪、知识沉淀、自我认知。

## 技术栈

| 层 | 技术 |
|------|---------|
| 后端 | Django 6.0 + DRF + django-cors-headers |
| 前端 | Vue 3 + TypeScript + Vite 7 + Pinia + Vue Router + Element Plus + ECharts |
| 数据库 | MySQL |
| Python | 3.14 |
| Node | ^20.19.0 \|\| >=22.12.0 |

## 快速开始

### 方式一：Docker 部署（推荐）

```bash
# 1. 克隆项目
git clone https://github.com/jiumigu/sycamore.git
cd sycamore

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env，修改 SECRET_KEY 和 DB_PASSWORD

# 3. 启动
docker compose up -d --build

# 4. 访问
# 前端：http://localhost
# 后端：http://localhost:8000/api/
# 管理后台：http://localhost:8000/admin/
```

### 方式二：本地开发

```bash
# 后端
cd backend
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver

# 前端
cd frontend
npm install
npm run dev
```

## 功能模块

| 模块 | 功能 |
|------|------|
| 📅 时间感知 | 日记流、任务清单（实时计时 / CSV 两步导入预演 / 每条记录的来源批次可查）、时间统计报表、活动追踪、日程视图；仪表盘「今天的三条线」（睡眠 / 午睡 / 流失，各有实测值与阈值） |
| 🎯 目标管理 | Goal→Milestone→Action 三层模型、良品率、快速创建 |
| 💰 财富管理 | 现金流热力图、月度日历、月度复盘、定期存款、资产盘点（科目主数据 / 资产负债表快照 / 负债与应收台账 / 分类规则 / 六项规划比率）、生存资源盘点（吃穿用数字还能撑多久） |
| 👥 关系管理 | 联系人、读者群体、成长记录、月末盘点 |
| 🏃 健康管理 | 步数追踪、体重管理、好朋友跟踪、身体健康自查 |
| 📚 知识沉淀 | 书籍管理、摘录馆（名言/典故/故事） |
| 🍰 小确幸 | 快乐记录（5–20 分，**奖励金额 = 分数**，单一刻度）、偏好图谱、快乐银行联动 |
| 🧭 自我认知 | 职业能量审计（工具箱） |
| 🌱 自我运转 | **入口在顶栏右上角下拉（不占侧边栏）**；KPI 的「制定 → 执行 → 复盘 → 事后分析」全生命周期；**阶段分两层**——长阶段只汇总（零 KPI，如「三年赎回期」），小阶段才跑 KPI；**阶段账本**页把一段长路的钱 / 时间 / 作品 / 小阶段一屏看完；**KPI 模板库可自定义增删改**（模板是拷贝不是引用，改删都不动已建阶段）、**每周/每月可修订下一期的目标**（「只这一期」或「从这一期起」）、周/月两把**正交**的尺子（月判定只看三问，未答 ⇒ 待答三问、不拿 KPI 顶档）、手工补记（撤销 = 冲销不删）、手动归档定格、阶段总结与配置变更留痕；「制定配置」页**只留本阶段 KPI**，模板库 / 按期修订 / 变更留痕**各自成页**、从右侧入口进 |
| 🛠️ 工具箱 | 时薪计算器、自由支配额度、用电记录、摘录管理、AI 问答库、决策追踪、职业能量审计 |
| 🏛️ 展厅 | **对外输出的策展空间**：品牌信息 + 能力馆（案例 / 技能）+ 作品馆。**数据引用、叙事手写**——数据从 Sycamore 里「选」，叙事在策展层「写」；作品馆直接引用作品库，媒体不重复上传 |
| 📦 作品 | 一件**从经历里长出来、以后还能再用**的东西（可以只有自己看）。七个「值得留下」打勾入口（里程碑完成 / 收件箱完成 / 读完一本书 / 日记标签「值得留」/ 摘录 / AI 问答 / 档案馆评价）→ **本周状态页末的收口台**把散的东西合成一件 → 作品列表与出口状态（只给自己 / 准备发 / 已发）；作品类型九类（文章 / 模型 / 模板 / 清单 / 其他手作 / 绘画作品 / 刺绣作品 / 教程 / 其他），月度 KPI 可按类型自动数；顶部计数卡可点：前三项筛清单、「待提炼」看明细。**周「输出次数」与月「内容输出」已改口径为「留下件数」**，与作品库**同一份数据** |

## 模块归档（瘦身）

基于 2026-08-27 审计（真实数据取证），月活近零的模块已收敛到侧边栏底部「已归档」弱化分组（半透明 + 归档标签），页面保留「此模块已归档，随时可重新启用」提示条。

**归档原则：数据、后端 API、路由全部保留，只收敛入口——可 100% 逆操作。**

> **「已归档」是软偏好，不是硬编码。** 侧边栏 `LayoutSidebar.vue:107` 优先读用户偏好表（`menu_key → is_favorite`），**无记录时**才回落到 `frontend/src/shared/config/menuConfig.ts` 的 `defaultArchived`。所以上表只是**没被改过的初始态**。

| 已归档模块 | 原入口 | 归档理由（数据量） |
|-----------|--------|-------------------|
| 数字资产 | `/dams` | 1 条 |
| 舞蹈记录 | `/dance` | 301 条 |

> 美食地图 `/food`（v3.63.8 起）与成长记录 `/relation/conflicts` 已不再占归档菜单，改从「旅行足迹」「关系管理」页头进入；数据、路由保留。

> 「个人良品率」（`/output`）**已取消默认归档**（v3.62.39）—— 它靠频率吃饭，藏起来等于自我否证；历史数据与入口都保留。
>
> 「自由支配额度」（`/toolkit/free-spending`）**不属于归档机制**：它在 `menuConfig.ts` 里**根本没有独立侧边栏入口**（v3.53 工具箱瘦身时移除），因此**无法通过菜单管理重新激活**——只能从「工具箱」聚合页进入。后端与工具本身都在。

> 旅行计划 `/travel/plans` **已重新启用**（v3.55+ 起与心愿 / 路线 / 足迹并称「旅行四件套」）；自 v3.63.8 起心愿单与路线推演改从旅行计划页头进入，不再占菜单项。

> **「三年赎回期」已不是独立模块**（v3.64.20）：侧边栏入口撤掉，六条接口下线，旧链接 `/redemption` 自动跳到「阶段账本」。它现在是自我运转下的一个**长阶段**（起止 = 阶段起止，本金在账本页改），`redemption` app 仅保留计算库。

**重新激活**：进「菜单管理」页（`/admin/menus`，`core/admin/views/MenuManager.vue`）把该模块勾为常用即可，偏好落库后侧边栏即时归位——**无需改代码**。（改 `menuConfig.ts` 的 `defaultArchived` 只影响从没被设置过的模块。）

## 设计理念

- 单人系统，所有数据本地存储
- 进度自动计算，不给自己骗自己的机会
- 模块间松耦合，通过 summary 聚合
- 支持脱敏开关，安全分享截图
